# AI・botの段階復旧と循環運営

## 最初の準備
設定 →「AI・botの復旧と循環運営」を開き、必要なら「13担当のひな形を用意」。Claude由来の各担当設定を含むひな形です。使わない担当は無効にし、自分のサービス名・設定・資料の場所・依存する担当・人間の操作を記入します。APIキー・パスワードは記入しません。

「復旧ZIPを確認して保存」で、入口、持ち主の操作表、fleet.json、担当別カードをまとめて保存します。これは運営情報専用です。通常の帳簿等は含みません。普段の全体バックアップも別に保存してください。ZIPは平文です。自分だけが読める場所へ保存し、公開リポジトリには置きません。

## 1体目から2体目、3体目へ
1. リセット後はZIPを展開し、00_START_HERE.mdを最初のAIへ渡します。fleet.jsonを新しい版のツールのこの画面で読み込み、内容を見て確定します。
2. ひな形の入口はAtlas（整理）、次はAegis（安全確認）。その後は必要な担当だけ順に戻します。依存関係は自分で変更できます。次に戻せる担当が画面に表示されます。
3. 担当カードの設定・資料・最後の途中地点を辿ります。人間が実サービスで復旧し、試運転できた担当だけ「復旧を確認」を押します。保存済みの確認は外部サービスが今動く証明にはなりません。
4. 2体目、3体目も同様に。全部を一度に戻す必要はありません。復旧の途中でも新しいZIPを保存でき、次回はそこから資料を辿れます。設定や前提担当が変わると後続も再確認が必要です。

## 人間の操作が必要なところ
- サービスへのログイン、アカウント本人確認、AI・botの作成、設定の貼り付け。
- Drive等の接続の再認証、読める範囲の指定、秘密情報の再設定（このZIPには保存しません）。
- 実サービス側の停止・再開、実行時刻・トリガーの設定、課金や上限の確認、試運転。
- 仕事の再開許可、結果の取り込みと完了判断。インポート後は再開許可が全てオフになります。
ツールからこれらを自動操作する機能はありません。ローカルの取消は、外で動いているAIを停止しません。外部の停止も人が行います。

## Driveを復旧の入口にする場合（任意）
既存キットのsetupは専用ルート直下に06_復旧入口を追加します（既存5フォルダも維持）。専用Googleアカウント・専用ルートに限定する既存条件はそのままです。setupや権限の設定、実行は人間が行います。
ZIPを展開して中身を06_復旧入口に自分で置き、00_START_HERE.mdとfleet.jsonの直接リンクを最初のAIへ渡します。各担当カードの資料リンクも実際の場所に合わせます。接続で読めなければ必要なファイルを自分で添付します。
運営情報の正本はツールで管理し、更新後のZIPを手動で置き直します。古い版は日付付きの別フォルダに保管し、入口は最新版1つに絞ります。自動同期・認証復旧・実botの自動生成は行いません。Driveに置く前に共有範囲を確認します。

## 普段の循環：作成 → 別担当が確認 → 差分修正
仕事にID、作成担当、別の確認担当、途中地点、次の作業、成果物の場所を記録。再開許可があり、復旧確認が済んだ担当の未着手・修正・確認待ちだけを受け渡します。停止・完了・保留は対象外です。
「次の作業パック」は1担当最大3件、全体最大15件。時間予算は初期5分、最大60分です。これは指示文の上限で、外部サービスの実行時間を強制停止する仕組みではありません。全文履歴を毎回渡さず、最後の途中地点と次の差分を渡します。
人間が保存したJSONをAIに渡し、指定形式の結果JSONを受け取って、差分を確認して取り込みます。作成担当は確認待ちへ、別担当の完了候補は持ち主が承認して初めて完了。修正は途中地点を保って作成担当へ戻ります。
同じ仕事を重複で準備しません。結果待ちの仕事を編集しても、元の受渡しを取り消すまで新しいパックに入りません。古い・重複・設定を変更する結果は拒否します。失敗時の自動再試行や常時実行はありません。

## 保存範囲と制限
最大30担当、300仕事、200履歴。入力は各項目5000文字まで、復旧JSONは1MBまで。本文を蓄えず資料の場所と途中地点に絞ります。履歴上限に達したらバックアップしてから持ち主が整理します。自動削除はしません。
SHA-256は破損確認用で署名ではありません。信頼できる自分のバックアップだけ読み込みます。秘密情報の検出は補助であり完全ではありません。ツールのロック中・競合中・保存失敗中は進めません。料金ゼロや負荷ゼロは保証せず、必要な担当と差分に絞って負荷を抑える方式です。
